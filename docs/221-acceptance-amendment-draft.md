# #221 acceptance amendment — draft for owner approval

Not posted. Proposed replacement for the lease/failure criterion, plus the approved compatibility requirements:

- Coordinate raw odds by canonical event/market identity across independent instances. Sorted batch claim and owner-fenced batch publication reuse the existing kernel. Equivalent and overlapping batches have one active owner per resource and no overlapping provider sends under valid ownership; stale owners cannot begin a new send, publish, renew or release a successor's claim. Preserve one batched upstream request for owned missing markets.
- Record claim time in PostgreSQL before provider send. Every caller respects a fixed 20-second cooldown per key against the recorded claim time. Caller freshness TTLs apply only to fetched_at. Exclude cooldown keys from the owned set, return them as stale when a real prior payload exists or unavailable otherwise, and fetch the other eligible keys normally. Inject publication failure, then issue a second request within 20 seconds: it adds zero provider calls. Then test a failed single-key attempt followed by a 12-key discovery request within 20 seconds: exactly one provider request for the other 11 keys and none for the failed key. Missing publication is unavailable; prior data is explicitly stale, not relabelled fresh.
- Do not automatically retry an ambiguous provider outcome. Later recovery after the applicable floor/TTL may repeat work whose earlier response was lost; the lease does not promise exactly-once external execution.
- Only odds move to the shared raw cache. Existing weather/view behavior stays unchanged. Current-schema execution matches main. Additive nullable lease columns stay in proposal SQL; a startup schema capability check selects the shared path without a runtime flag, with separate schema activation/restart planning. Legacy instances write without fencing; require draining them before shared activation to prevent rollout duplicates and unfenced publication, unless the owner explicitly accepts that overlap risk.
- Prove two-instance and separate-process behavior with local mocked providers, deterministic work counts and the 240-resource synthetic fixture. The 8 MiB logical payload ceiling is fixture-only. Publish an empty slice for absent provider markets, matching main. Count follower reads, failed claims and renewals using the real 250 ms / 45-second settings. The owner-approved #61 full warm pre-provider deadline is 90 ms including four cache statements and admission; report its budget split with checkpoint 1. Local qualification does not certify hosted full-path latency.
